# Releasing and publishing to the KiCad PCM

The plugin is distributed through KiCad's **Plugin and Content Manager** (PCM).
Reference: [KiCad addons guide](https://dev-docs.kicad.org/en/addons/) and the
[PCM v1 schema](https://go.kicad.org/pcm/schemas/v1).

![release](https://www.plantuml.com/plantuml/proxy?cache=no&fmt=svg&src=https://raw.githubusercontent.com/kevinwysocki/kicad_release_wizard/main/doc/diagrams/release.puml)

<sub>Source: [diagrams/release.puml](diagrams/release.puml)</sub>

## Files

| Path | Role |
|---|---|
| `pcm/metadata.json` | Package metadata template (no `version`, no `download_*`): name, descriptions, identifier, licence, status, KiCad versions, runtime |
| `pcm/build_package.py` | Builds `dist/<identifier>-<version>.zip`, `dist/metadata.json` (to submit) and `dist/icon.png` |
| `.github/workflows/release.yml` | On a version tag, runs the build and publishes the GitHub release with these three files |
| `resources/icon_64.png` | PCM icon (64×64), generated by `resources/make_logo.py` |

## Package layout

```
plugins/                 installed as <KiCad 3rdparty>/plugins/com_github_kevinwysocki_kicad-release-wizard/
  __init__.py, *.py      the plugin
  job_scripts/*.py       copied to <project>/.scripts/ on Generate
  resources/logo.png     24×24 toolbar icon
  LICENSE, requirements.txt
resources/icon.png       64×64 PCM icon
metadata.json            template + version, without download_* keys
```

The archive is reproducible (sorted entries, fixed timestamps, LF line endings): the same
sources give the same SHA-256 locally and in CI.

## Release procedure

1. Update `pcm/metadata.json` if needed (`status`, `kicad_version_max`, descriptions).
2. Optionally check locally: `python pcm/build_package.py <version>` (writes `dist/`).
3. Commit, tag with the bare version number and push:
   ```
   git tag -a 0.0.2 -m "KiCad Release Wizard 0.0.2"
   git push origin main 0.0.2
   ```
4. The *Release* workflow builds the package and creates the GitHub release (marked
   *pre-release* while the status is not `stable`), with the zip, `metadata.json` and
   `icon.png` attached. Re-run it for an existing tag from the *Actions* tab
   (*Run workflow*, tag input).
5. Submit to KiCad: fork [gitlab.com/kicad/addons/metadata](https://gitlab.com/kicad/addons/metadata)
   and open a merge request adding (first release) or updating:
   ```
   packages/com.github.kevinwysocki.kicad-release-wizard/metadata.json   ← dist/metadata.json
   packages/com.github.kevinwysocki.kicad-release-wizard/icon.png        ← dist/icon.png
   ```
   For an update, add the new entry from `dist/metadata.json` to the `versions` list of the
   existing file (older versions stay listed).

## Metadata choices

| Field | Value | Why |
|---|---|---|
| `identifier` | `com.github.kevinwysocki.kicad-release-wizard` | GitHub-based reverse-DNS namespace; dash instead of underscore (identifier rules) |
| `status` | `testing` | Until 1.0.0 |
| `kicad_version` / `kicad_version_max` | `9.0` / `10.99` | Jobsets need KiCad 9; the SWIG bindings are planned for removal in KiCad 11 |
| `runtime` | `swig` | Action plugin on the `pcbnew` SWIG bindings; the plugin will move to the IPC API for KiCad 11 |
| `license` | `MIT` | Open-source and GPL-compatible, as required for Python packages |
| `description` | ≤ 150 characters | Addons guide limit (`build_package.py` checks it) |

The PCM does not install Python packages for SWIG plugins: `description_full` tells users to
install PyMuPDF in their system Python.
